# 新旧 AI 引擎对抗测试报告 — 规则 0（成三棋）× 20 局

- 日期：2026-09-12
- 对局程序：`benchmark/AIBenchmark.exe`（本报告同目录）
- 对方引擎配置、逐局详情与可回放棋谱见本目录。

## 对阵配置

| | 旧引擎（2026年前） | 新引擎（当前） |
|---|---|---|
| 代码版本 | 提交 `a588f4a`（2018-12-23）原样提取，零算法改动 | 当前 `NineChess/src` 核心 |
| 搜索 | Alpha-Beta，**深度 8** | 迭代加深 Alpha-Beta，**深度 10**（中局动态 +2，平均完成 11.3 层） |
| 线程 | **单线程**（2018 版搜索本身即单线程；置换表查询在其源码中即被注释停用） | **8 线程**（Lazy SMP，按题目要求指定） |
| 每步限时 | 10 秒强制出招 | 10 秒时间预算强制出招 |
| 其他 | 原样（随机走法排序） | 默认搜索特性全开（PVS/静默搜索/强制提子延伸/LMR/重复惩罚等），根节点随机 gap=60（项目对局默认，每局独立种子保证 20 局不重复） |

赛制：奇偶局交替执先（各 10 局）；累计 100 条走子命令未分胜负判和（与 GUI 控制层语义一致）。

## 总比分（20 局）

| 结果 | 局数 |
|---|---|
| **旧引擎胜** | **10** |
| **新引擎胜** | **5** |
| **和棋** | **5** |

计分（胜1和0.5）：旧 12.5 : 新 7.5。**旧算法以 10:5 领先。**

## 按执先手拆分（关键发现）

| 执先方 | 先方战绩 | 后方战绩 |
|---|---|---|
| 旧引擎执先（10 局） | **10 胜 0 和 0 负（100% 转化）** | 新执后：0 胜 0 和 10 负 |
| 新引擎执先（10 局） | 5 胜 5 和 0 负（50% 转化） | 旧执后：0 胜 5 和 5 负 |

- 规则 0 在此深度下**先手优势压倒性**：双方执后手都是 0 胜。
- 比赛胜负完全由"执先转化率"决定：旧引擎执先 10 局全部取胜；新引擎执先 10 局只赢 5 局，另外 5 局被旧引擎磨和（100 步判和）。
- 这与新引擎自测报告（Readme/AI_SUMMARY）中已记录的弱点一致："引擎偏保守、残局转化偏慢，多数对局以步数上限平局收场"。旧引擎纯子力评估反而更"狠"，领先即求杀。

## 棋谱

- 20 份棋谱在本目录：`rule0_g01..g20_*.txt`，格式为工程标准纯命令流（首行 `r0s100t0`，0-based 坐标）。
- 已抽样在官方 `NineChessConsole` 回放验证通过（结果与记录一致）。

## 复现方式

```bat
cd benchmark
build_benchmark.bat
AIBenchmark.exe 0 0 20 8 10 10000 8
```

参数：`起始规则 结束规则 每规则局数 旧深度 新深度 每步限时ms 新引擎线程数`。

## 备注

- 规则 1/2/3 未纳入本报告：冒烟测试发现 2018 版模型在这三套规则下与现行模型存在规则实现层面的状态分歧（成三判定/禁点/编号三连历史等历史 bug），按约定"以走子互接受为限、分歧用兜底着法消化"也能跑完全部对局，但对抗纯度下降，故仅正式测试规则 0。
- 旧引擎为 2018 年原代码（单线程；其静态置换表在源码中即被注释停用），未做任何算法修改；仅用 `namespace` 隔离以便与新引擎同进程对弈。
