# 九连棋 NineChess
## 更新历史 Update History：
### 2026/09/15    v2.2
    1. AI 搜索增强：新增静默搜索、浅层剪枝、强制提子延伸、LMR 迟到走法减搜、PVS 零宽试探、Aspiration 窗口与重复局面惩罚（含根局面与真实对局历史），同深度耗时显著下降。
       AI search improvements: added quiet search, shallow pruning, forced-capture extension, LMR late-move reductions, PVS zero-width probes, aspiration windows and repetition penalties (including the root position and the real game history), noticeably cutting the time needed to reach the same depth.
    2. 置换表升级为定长桶数组 1M 条（16 字节槽位）并改为每个 AI 实例私有（先手/后手分表互不共享）；修复胜负分 ply 相对化与后手根节点随机视角缺陷。
       Transposition table upgraded to a fixed-length bucket array of 1M entries (16-byte slots) and made private to each AI instance (separate tables for the first and second player, never shared); fixed a ply-relative score bug and a defect in the second player's randomised root view.
    3. 根节点随机改为默认仅开局前 10 步生效（randomGap 16），中残局恢复纯最优；GUI 默认 AI 配置调整为思考深度 10、每步限时 5 秒。
       Randomised root selection now applies only to the first 10 moves by default (randomGap 16), with pure best-move play in the middle and endgame; the default GUI AI configuration is now search depth 10 and 5 seconds per move.
    4. AI 设置对话框深度上限 20、限时上限 60 秒；勾选先手 AI 且未开局时自动开局；棋谱列表追加后自动滚动到底；自动运行模式最低 0.5 秒/步。
       The AI settings dialog now allows depth up to 20 and time up to 60 seconds; ticking the first-player AI before the game starts auto-starts it; the game-record list scrolls to the bottom after an append; auto-play mode has a minimum of 0.5 s per move.
    5. GUI 工具集升级为 MSVC v143（VS2022）；新增三代引擎同进程对抗与自对弈基准（benchmark），默认配置对 2026-05 版 80 局 50:13、对 2018 版一局不失。
       The GUI toolset was upgraded to MSVC v143 (VS2022); a benchmark for in-process matches and self-play across three engine generations was added, with the default configuration beating the 2026-05 version 50:13 over 80 games and never losing to the 2018 version.
    6. 新增界面多语言：内置简体中文、繁体中文、英语、日语、韩语、德语、法语、俄语、西班牙语、葡萄牙语 10 种语言；“选项 → 设置 → 语言”菜单即时切换（原不可用的“设置”项改为语言子菜单），选择写入 QSettings 并在下次启动沿用，首次启动按系统语言自动判定。
       A multi-language UI was added: ten built-in languages (Simplified and Traditional Chinese, English, Japanese, Korean, German, French, Russian, Spanish, Portuguese) switchable at runtime under "Options → Settings → Language" (the previously disabled "Settings" entry now hosts the language submenu); the choice is stored in QSettings and reused on the next launch, with the system locale deciding the first run.
    7. 翻译与版本号纳入工程管理：模型层不依赖 Qt，规则名、规则说明与状态栏提示改由可注入的翻译钩子输出（`setTextTranslator()` / `translateText()`），提示文本按“模板 + 占位符实参”保存，因此切换语言无需重走棋步；界面译文源码 `NineChess/translations/*.ts` 由 lupdate 生成、lrelease 产出 .qm，经 ninechesswindow.qrc 以 `/i18n` 前缀打包进 exe；版本号收敛为单一来源 `NineChess/src/ninechess_version.h`，同时驱动 exe 资源版本、窗口标题与“关于”对话框。
       Translations and the version number are part of the project: the model stays Qt-free and its rule names, rule descriptions and status-bar tips go out through an injectable translation hook (`setTextTranslator()` / `translateText()`), with tips stored as template plus placeholder arguments so a language switch needs no replay; UI translations live in `NineChess/translations/*.ts` (generated by lupdate, compiled by lrelease into `.qm`) and are packed into the executable under the `/i18n` prefix via `ninechesswindow.qrc`; the version number has a single source `NineChess/src/ninechess_version.h`, driving the executable version resource, the window title and the About dialog.

### 2026/09/06    v2.1
    1. 棋谱升级为纯命令流格式：首行为对局配置命令 r<规则>s<限步>t<限时>（如 r2s100t10，段可省略，0=不限），打开时由控制层切换规则并恢复限时限步。
       Game records were upgraded to a pure command-stream format: the first line is the setup command r<rule>s<steps>t<minutes> (for example r2s100t10; segments are optional and 0 means unlimited), and the controller switches the rule and restores the time/step limits when the file is opened.
    2. 平局/认输沿用 ==/-0/-1 命令记录；超时判负等外部裁定终局在保存时补写负方认输命令，回放可完整还原终局。
       Draws and resignations keep using the ==/-0/-1 commands; externally adjudicated endings such as a timeout loss append the loser's resignation command on save so that replay restores the ending exactly.
    3. 更早版本无配置行的棋谱保持兼容，按当前规则回放；配置命令解析 parseSetupCommand() 位于核心层，GUI 与控制台共用。
       Older records without a setup line stay compatible and are replayed under the current rule; the setup command is parsed by parseSetupCommand() in the core, shared by the GUI and the console.
    4. GameController 拦截配置命令（模型层不感知限时限步），新增 getWinner()/isEndedByAdjudication()；控制台识别配置命令并回显。
       GameController intercepts the setup command (the model is unaware of time and step limits) and gained getWinner()/isEndedByAdjudication(); the console recognises the setup command and echoes it.

### 2026/04/26    v2.0
    1. 重整核心模型边界，新增 ninechess_common.h，梳理 Rule、ChessData、位棋盘状态与新字段命名。
       The core model boundaries were reorganised, ninechess_common.h was added, and Rule, ChessData, the bitboard state and the new field naming were cleaned up.
    2. 将限时、限步、超时裁定、AI 超时强制出招等赛制逻辑集中到 GameController，giveup() 仅保留认输语义。
       Match logic such as time limits, step limits, timeout adjudication and forcing an AI move on timeout was consolidated into GameController, leaving giveup() with the meaning of resignation only.
    3. 重写并重命名 Alpha-Beta AI 为 ninechess_ai_ab.*，使用位棋盘、快速接口、迭代加深和对称置换表。
       The Alpha-Beta AI was rewritten and renamed to ninechess_ai_ab.*, using a bitboard, fast interfaces, iterative deepening and a symmetric transposition table.
    4. 新增 NineChessConsole 命令行测试工程，支持规则切换、命令回放、历史查看、撤销、认输、判和与启动参数。
       The NineChessConsole command-line test project was added, supporting rule switching, command replay, history browsing, undo, resignation, draw adjudication and startup arguments.
    5. 新增 RuleHarness 与 PowerShell 回归脚本，覆盖四套规则白盒测试和 Console 黑盒测试。
       RuleHarness and PowerShell regression scripts were added, covering white-box tests for all four rules and black-box tests for the console.
    6. 同步 Visual Studio、qmake 工程和 /utf-8 编译设置，统一 UTF-8 without BOM 与 CRLF 文本格式。
       The Visual Studio and qmake projects and the /utf-8 compiler setting were synchronised, unifying UTF-8 without BOM and CRLF text formatting.
    7. 清理本地生成文件，并更新 README、界面工程文件和图标资源说明。
       Locally generated files were cleaned up, and the README, UI project files and the icon resource description were updated.
